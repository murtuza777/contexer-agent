## Q1. Timeline: what did each incumbent ship, when, by category (planning/specs, parallel/background agents, self-verification, code review, CI, memory/context, multi-agent orchestration, governance)?

### Takeaway
Between Feb 2025 and Oct 2026 every major incumbent converged on the same stack: a terminal/IDE agent, cloud/background agents in sandboxes, parallel agents in worktrees, plan mode, a per-vendor "agent dashboard", built-in browser or computer-use self-testing, a bundled PR reviewer, a security scanner, and scheduled/event-triggered automations. By Sept–Oct 2026 the frontier moved to (a) long-running coordinator agents (Cursor Projects, Claude dynamic workflows/Routines, Antigravity 2.0), (b) "agent merge" (agents that drive a PR through review feedback, CI failures and conflicts to merge), and (c) first steps into production (Cursor Rollouts; Copilot app Sentry/PagerDuty integrations) — but almost all of it is vendor-locked and self-graded.

## Q3. What do practitioners and analysts say is still missing in late 2026?

### Takeaway
The consensus constraint has shifted from writing code to **verifying** it: surveys show review/validation is the #1 bottleneck, agents raise code volume without raising shipped output, trust is conditional on easy verification, and benchmark "passes" overstate mergeability by ~24pp. Specific holes: user-level end-to-end acceptance proof, spec→acceptance traceability, non-gamed self-reports, cross-vendor orchestration and governance, production feedback loops, and cost controls.

### Cited Findings
**Verification / review bottleneck**

[V] — [Qodo](https://www.qodo.ai/blog/state-of-ai-code-quality-report-2026/)

[S] — [AgentConn](https://agentconn.com/blog/verify-dont-review-coding-agents-2026/), [reptile.haus](https://reptile.haus/journal/the-verification-bottleneck-why-your-teams-real-constraint-is-no-longer-writing-code/)

- **White space for a third-party autonomous layer (ranked by evidence strength):**

Evidence: METR 24pp grader/maintainer gap; reward hacking (≥16% illegitimate long-task successes); Qodo/Sonar/SO trust-when-verifiable data; incumbents' checks are self-graded and non-blocking.
  2. *Spec→acceptance traceability*: only 45% of leaders can trace AI activity to code (Qodo); 85% of devs say requirements are the most trusted context (SO). Plan modes produce plans but no incumbent ties each requirement to a passing, user-observable check through merge.
  3. *Cross-vendor control plane*: each vendor has its own dashboard; GitHub Agent HQ is the only multi-vendor surface and is GitHub/Copilot-billed; Cursor is building a rival forge. Neutral orchestration + policy + audit across Claude/Codex/Copilot/Cursor/Gemini remains open but GitHub is the strongest incumbent for it.
  4. *Regression protection/merge gating*: agent-merge features (VS Code, Copilot app) will drive PRs to merge; Claude Code Review is deliberately non-blocking. A vendor-neutral gate that blocks on failed user-level checks is unowned.
  5. *Production → agent loop*: only Cursor (Rollouts, own platform) and partner integrations (Sentry/PagerDuty in Copilot app) exist; no auto-rollback; low adoption (20%).
  6. *Cross-vendor cost governance*: controls are per vendor; orgs juggling several agents have no unified spend/limit view.
- Incumbents are fast followers: any layer that is merely a better single-vendor harness, dashboard, or PR commenter is likely to be bundled within 3–6 months (pattern: browser testing, review, sandbox, dashboards all bundled 2025–26).
