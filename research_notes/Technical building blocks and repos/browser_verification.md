# Browser testing and verification building blocks, AI end-to-end testing agents, and benchmarks (for Contexer's acceptance-check layer)

State as of 2026-10-14. Star counts, licenses, languages and last-push dates come from `gh api repos/OWNER/REPO` run on 2026-10-14 unless noted. "Vendor claim" marks statements made by a project about itself that were not independently checked. Contexer context: Python 3.11+, Playwright Python, a closed JSON check format (steps: click, fill, press, select, check, hover, goto, wait; expectations: visible, hidden, count, text, value, attribute, css, url, title, no_errors; comparators equals, contains, matches, changed), fresh Chromium context per check, verdicts labelled proven / LLM-judged / heuristic.

## Q1. Playwright in 2026: ARIA snapshots, traces, video, clock, routing/HAR, Test agents, MCP. What can Python use, and what is Node-only?

### Takeaway
Playwright Python 1.64 (released 2026-10-13) covers almost everything Contexer needs at runtime. That includes ARIA snapshot assertions with partial and regex matching, an `"ai"` ARIA snapshot mode with `page.get_by_ref()`, `locator.normalize()`, traces that record an ARIA snapshot and a screenshot on every action, a screencast API with chapters, and console, page-error and request accessors. The main Node-only gaps are the screenshot-comparison assertion (`toHaveScreenshot`), which maintainers said in April 2026 they have no plans to add to Python, the Playwright Test agents (planner, generator, healer), the HTML reporter, and snapshot-update tooling.

**ARIA snapshots (all available in Python)**
- `expect(locator).to_match_aria_snapshot()` arrived in 1.49 and works on a whole page since 1.60. `page.aria_snapshot()` and `locator.aria_snapshot()` return YAML. The format is `- role "name" [attr=value]` with indentation for nesting. Templates are constraints rather than full serializations. You can omit a name or attributes to match partially, use `/regex/` for names and text, and check `/url` on links. Supported attributes are checked, disabled, expanded, invalid, level, pressed and selected — [Playwright Python docs: ARIA snapshots](https://playwright.dev/python/docs/aria-snapshots)
- `/children` controls how strictly children match: `contain` (the default), `equal` or `deep-equal`. Sibling order matters and matching is case-sensitive. `/children` and `/url` were added in 1.52 — [ARIA snapshots](https://playwright.dev/python/docs/aria-snapshots), [Python release notes](https://playwright.dev/python/docs/release-notes)
- 1.59 (Python) added `page.aria_snapshot()`, `depth` and `mode` options on `aria_snapshot()`, `locator.normalize()` ("converts a locator to follow best practices like test ids and aria roles"), `page.pick_locator()`, and `clear_console_messages()`/`clear_page_errors()` — [playwright-python v1.59.0](https://github.com/microsoft/playwright-python/releases/tag/v1.59.0)
- 1.60 (Python) added a `boxes` option that appends `[box=x,y,width,height]` to each ARIA node ("useful for AI consumption"), page-level `to_match_aria_snapshot`, a `description` option on `get_by_role()`, and a `pseudo` option on `to_have_css()` for `::before`/`::after` — [playwright-python v1.60.0](https://github.com/microsoft/playwright-python/releases/tag/v1.60.0)
- 1.64 (Python, 2026-10-13) added `page.get_by_ref()`, which "locates an element by its aria ref, such as `e2`, reported by page.aria_snapshot() in the `"ai"` mode". It also added `locator.within()`, and `page.content(include_shadow=...)`. Breaking change: elements inside hidden iframes now count as hidden — [playwright-python v1.64.0](https://github.com/microsoft/playwright-python/releases/tag/v1.64.0)
- Node 1.63 also added `ariaSnapshotJSON()` with `mode`, `depth` and `boxes`. The Python 1.63 notes do not list a JSON variant, so that is unverified for Python — [Node release notes](https://playwright.dev/docs/release-notes)
- The docs warn about snapshot testing itself: it suits volatile content poorly, reviewers may accept changes without understanding them, and large snapshots are hard to read — [ARIA snapshots](https://playwright.dev/python/docs/aria-snapshots)

### Inferences
- **Playwright Python: BUILD ON (already in use).** Each Contexer expectation type has a native Python assertion. ARIA snapshots in partial-template form would add a strong "proven" structural expectation type (for example `aria` with `contain`/`equal` children) that holds up better than CSS selectors. Pin ≥1.64 to get `get_by_ref` and `normalize()`.
- **A re-location path that keeps checks strict, built from Python primitives:** (1) capture `page.aria_snapshot(mode="ai")` (with `boxes=True` when a vision model is involved); (2) have a model or heuristic pick a ref; (3) resolve it with `page.get_by_ref()`; (4) convert it to a durable role or test-id locator with `locator.normalize()`; (5) re-run the unchanged expectation. Only the target may change, never the comparator or expected value. This mirrors what the Playwright healer does, minus its "skip the test" outcome. Contexer should treat "functionality broken" as a FAIL, not a skip.
- **Evidence:** `tracing.start(snapshots=True, screenshots=True, aria_snapshots=True, screen_snapshots=True)` per check context, plus `screencast.show_chapter()` per check, gives a self-contained trace.zip and a narrated video. The trace viewer runs client-side, so a hosted trace.zip URL can serve as a GitHub check `details_url`.
- **Determinism:** the clock API, `route`/`route_from_har`, and per-check `clear_console_messages()` make "proven" verdicts reproducible. Recording a HAR on the first passing run and replaying it in regression mode is an option for apps with external calls.
- **Playwright Test Agents: BORROW IDEAS (Node-only).** Copy the planner, generator, healer split and the seed-test idea. Do not copy the healer's freedom to make "data fixes" or to skip, because both can weaken a check.
- **Playwright MCP: BORROW IDEAS.** Its `browser_verify_*` vocabulary maps closely onto Contexer's expectations, and `browser_generate_locator` mirrors the ref-to-locator step. It is useful to the coding agent while it explores, but it is not a Python runtime for Contexer.
- **Visual checks:** Python has no `to_have_screenshot`, so Contexer must own baseline storage, diffing and update/approve semantics (see Q4).

### Gaps
- I could not confirm whether `ariaSnapshotJSON()` (Node 1.63) or the `npx playwright trace` agent CLI (Node 1.59) is exposed in Python 1.64. The Python release notes do not mention them.
- I found no documented pytest flag for updating ARIA snapshot templates in Python. It appears to be a Playwright Test (`--update-snapshots`) feature.
- The exact grammar of the `"ai"` mode output (ref format, which nodes get refs) was not read. Only the release-note description is cited.

## Q2. Agentic browser frameworks (Stagehand, Browser Use, Vercel agent-browser, chrome-devtools-mcp, Midscene.js, Skyvern): how they locate elements, and which can cache actions so later runs need no LLM?

### Takeaway
Several of these can replay without an LLM: Browser Use (`rerun_history` with a cascading deterministic element matcher), Midscene (YAML cache of plans and XPaths, assertions never cached), Skyvern (`run_with: code`, which runs cached generated Python scripts), and Stagehand (server-side cache, but only on Browserbase in v4). None suits Contexer as a runtime: each is an agent framework with its own driver, mostly TypeScript, or AGPL. Their caching and re-matching designs are the most useful ideas to borrow, especially Browser Use's EXACT → STABLE → XPATH → AX_NAME → ATTRIBUTE cascade and Midscene's rule against ever caching assertion results.

### Cited Findings
**Stagehand (browserbase/stagehand)**
- MIT, 25,665 stars, TypeScript, last push 2026-10-14. Latest releases: `@browserbasehq/stagehand@3.7.3` and `stagehand-server-v3/v3.7.6` on 2026-08-28. The README now documents v4 docs paths — [GitHub](https://github.com/browserbase/stagehand)
- In v4 Stagehand is "one complete browser driver across TypeScript, Python, and Go" and "runs as an extension next to the browser". It exposes `act`, `observe` and `extract`. `observe()` "returns real selectors", and `act` "self-heals when the site redesigns its form" (vendor claim). It uses "hybrid accessibility-tree trimming" and emits OTel traces — [GitHub README](https://github.com/browserbase/stagehand)
- The separate stagehand-python repo was archived on 2026-08-20 (517 stars). The Python SDK now lives in the monorepo at `packages/sdk-python`. The Java, Kotlin, PHP, .NET, Go and Rust SDK repos are also archived — [stagehand-python](https://github.com/browserbase/stagehand-python), [browserbase org](https://github.com/browserbase), [sdk-python README](https://github.com/browserbase/stagehand/tree/main/packages/sdk-python)
- In v3, caching had a local `cacheDir` that replays `act()` and agent steps "with no LLM calls", plus a Browserbase server cache with `cacheStatus` HIT or MISS. To refresh the local cache you delete the directory — [Stagehand v3 caching](https://docs.stagehand.dev/v3/best-practices/caching)
- In v4, caching is server-side only: "Browserbase manages the cache… With a local browser, the `cache` option has no effect and every call runs inference." The key is built from the instruction, the page content and the options. Cached `act()` replays "run deterministically with self-healing turned off", and if the recorded selector fails, Stagehand falls back to full inference. Python passes `cache=True` and reads `result.metadata.cache.status` — [Stagehand v4 caching](https://docs.stagehand.dev/v4/best-practices/caching)

**Browser Use (browser-use/browser-use)**
- MIT, 117,955 stars, Python ≥3.11, last push 2026-10-09, release 0.13.11 on 2026-10-07. It can drive "a local browser, a Browser Use Cloud browser, or an existing remote browser over CDP" — [GitHub](https://github.com/browser-use/browser-use), [releases](https://github.com/browser-use/browser-use/releases)
- `agent.load_and_rerun(history_file)` / `rerun_history()` replays saved agent history. During a rerun an LLM is used only for 'extract' actions (an "AI step" that re-reads the page) and for an optional final AI summary based on a screenshot. The history can also be scanned for variables to substitute — [rerun_history example](https://github.com/browser-use/browser-use/blob/main/examples/features/rerun_history.py)
- When a historical element's index changes, `_update_action_indices` uses a "Cascading matching strategy". It tries EXACT (the full `element_hash`, including attributes and `ax_name`), then STABLE (a hash "with dynamic CSS classes filtered out (focus, hover, animation, etc.)"), then XPATH, then AX_NAME (same tag and same accessible name), then a unique ATTRIBUTE fallback. It logs the level that matched — [agent/service.py](https://github.com/browser-use/browser-use/blob/main/browser_use/agent/service.py)
- browser-use/workflow-use (AGPL-3.0, 4,225 stars, last push 2026-10-09) offers "Deterministic, Self Healing Workflows (RPA 2.0)". It turns an agent run into a "semantic workflow with parameters" that can be reused "with different inputs, no AI needed", and falls back to Browser Use when a step fails. The README says "very early development… don't recommend using this in production" — [GitHub](https://github.com/browser-use/workflow-use)
- browser-use/browser-harness (MIT, 18,431 stars, last push 2026-10-13) calls itself a "Self-healing harness that enables LLMs to complete any task" — [GitHub](https://github.com/browser-use/browser-harness)

**Vercel agent-browser (vercel-labs/agent-browser)**
- Apache-2.0, 43,962 stars, written in Rust, last push 2026-10-14, v0.39.1 on 2026-10-13. It is a "Fast native Rust CLI" that drives Chrome (Chrome for Testing) over CDP. Safari/WebDriver, Lightpanda and Obscura backends are also listed. It does not require Playwright — [GitHub](https://github.com/vercel-labs/agent-browser), [releases](https://github.com/vercel-labs/agent-browser/releases)
- `snapshot` returns an accessibility tree with refs (`@e2`). `-i` limits it to interactive elements, and `-c`, `-d`, `-s` and `--json` adjust the output. Elements can also be found with CSS, `text=`, `xpath=` and semantic `find`. `--annotate` overlays ref labels on a screenshot. Verification commands include `is visible|enabled|checked`, `get text|attr|count|styles`, `wait`, `screenshot --if-changed --threshold`, `record start/stop` (video), `trace`, `profiler`, `console`, `errors`, `network requests`/`har`, `diff` (snapshot, screenshot or URL), and `a11y` (an embedded axe-core audit). `batch` runs a fixed command list from arguments or JSON on stdin. Installation is via npm, Homebrew or Cargo, and no Python package is mentioned — [GitHub README](https://github.com/vercel-labs/agent-browser)

**chrome-devtools-mcp (ChromeDevTools/chrome-devtools-mcp)**
- Apache-2.0, 53,523 stars, TypeScript, last push 2026-10-14, v1.10.1 on 2026-09-23. It uses Puppeteer and needs Node.js LTS and Chrome stable. Usage statistics are on by default (`--no-usage-statistics`), and performance tools may send trace URLs to CrUX (`--no-performance-crux`). A CLI is available for non-MCP use — [GitHub](https://github.com/ChromeDevTools/chrome-devtools-mcp)

**Midscene.js (web-infra-dev/midscene)**
- MIT, 15,259 stars, TypeScript, last push 2026-10-14, v1.15.4 on 2026-10-14. It is "vision-driven": the model looks at the screen, acts and checks the visible result. Tests are written in YAML, or as a `PlaywrightAgent` with `aiAct`, `aiTap`, `aiInput`, `aiAssert` and `aiQuery`. It produces interactive HTML reports with screenshots, element locations and the AI's decision process. Supported models include Qwen3.x, Doubao-Seed-2.1, GLM-4.6V, gemini-3.5-flash and UI-TARS. Vendor claim: 58 of 60 AppControlBench tasks for $0.59 in total — [GitHub README](https://github.com/web-infra-dev/midscene)
- Caching: plans (`ai`/`aiAct`) and element XPaths (`aiLocate`/`aiTap`, web only) are cached in `./midscene_run/cache/*.cache.yaml`. A cached XPath is reused only if it is still valid and its text matches, otherwise the AI runs again. `aiBoolean`, `aiQuery` and `aiAssert` are never cached ("Never cache query results"). Strategies are read-write, read-only (for CI, with `flushCache()`) and write-only. `flushCache({cleanUnused:true})` prunes unused entries. The cache does not work on canvas, cross-origin iframes or closed shadow DOM. Vendor example: a run dropped from 51 s to 28 s on a cache hit — [Midscene caching docs](https://midscenejs.com/caching.html)
- Python: only community ports exist, such as Python51888/Midscene-Python (MIT, 133 stars, last push 2025-10-04) — [GitHub](https://github.com/Python51888/Midscene-Python)

**Skyvern (Skyvern-AI/skyvern)**
- AGPL-3.0, 23,195 stars, Python, last push 2026-10-14, v1.0.56 on 2026-10-14. It uses vision LLMs plus Playwright and offers a "Playwright-compatible SDK" with `page.validate(prompt)` returning a bool. Vendor claims: WebVoyager 85.8% and WebBench 64.4%. Anti-bot features are cloud-only — [GitHub README](https://github.com/Skyvern-AI/skyvern)
- Script generation: "converts workflow runs into executable Python code that can be cached and reused", which enables `run_with: code`. Caching is progressive, per executed block. Conditional blocks always run through the agent. When a block lacks a cached script, the run falls back to `run_with: agent` — [script_generations/CLAUDE.md](https://github.com/Skyvern-AI/skyvern/blob/main/skyvern/core/script_generations/CLAUDE.md)

### Inferences
- **Stagehand: AVOID as runtime, BORROW IDEAS.** v4 swaps Playwright for its own driver, and LLM-free replay now requires the Browserbase cloud. The ideas worth taking are: use `observe()`-style resolution that returns a concrete selector to store; key the cache on instruction plus page content; replay cached actions deterministically with healing off; and fall back to inference only on a miss.
- **Browser Use: BORROW IDEAS (strongest fit for re-location).** Its cascade can be ported to Playwright Python: store with each check target an element fingerprint (role, accessible name, tag, stable attributes such as test-id/name/href, XPath, and the hash after removing volatile classes). Re-locate in order: exact, then stable, then role+name, then unique attribute, and only then an LLM over the `"ai"` ARIA snapshot. Record the match level in the verdict ("re-located at AX_NAME level") so a human can audit drift. Do not take a dependency on it, since it is a full agent that drives CDP directly.
- **workflow-use: AVOID** (AGPL-3.0, self-described as not production-ready).
- **agent-browser: BORROW IDEAS / optional coding-agent tool.** Its ref snapshots, `diff snapshot|screenshot`, `batch` JSON and embedded axe show what a "CLI for agents" verification surface looks like. It has no Python API.
- **chrome-devtools-mcp: BORROW IDEAS / optional evidence source.** `lighthouse_audit` and performance traces could feed optional non-functional checks. Its telemetry and CrUX defaults would need to be switched off.
- **Midscene: BORROW IDEAS, AVOID as runtime.** Two design rules map directly onto Contexer's verdict labels: actions can be cached but assertions must always re-execute, and CI should use a read-only cache. Midscene's vision-first locating suits checks on canvas content, which DOM tools cannot inspect.
- **Skyvern: AVOID** (AGPL-3.0, platform-sized). Borrow the progressive caching idea: compile what the agent did into code, run that code, and fall back to the agent per block.

### Gaps
- I did not verify whether Browser Use's rerun re-checks anything beyond locating the element (for example, whether the action's effect is verified). Its final "AI summary" is LLM-judged.
- Stagehand v4 Python SDK maturity (release cadence on PyPI) was not checked.
- I found no published accuracy numbers for any of these caching or re-matching schemes (false re-match rate). All the claims are vendor documentation.

## Q3. Open-source AI end-to-end testing agents (Shortest, Magnitude, TestZeus Hercules, LaVague, and 2026 repos with traction): natural-language or code specs, and how do they control flakiness?

### Takeaway
The 2024–25 generation has mostly stalled or pivoted. Shortest's last release was in April 2025. Magnitude's flagship repo was repurposed as an inference engine, and its browser agent was last pushed in February 2026. LaVague has been dormant since January 2025, and Hercules is AGPL. The 2026 projects with real traction are mostly source-available rather than OSI open source, and several aim squarely at Contexer's niche of "verify the coding agent's work in a real browser": millionco/expect (FSL), bug0inc/qa-agent (FSL), TestSprite CLI (a client for a SaaS), and Explorbot (ELv2). They take natural-language specs. Flakiness controls are step caching with AI fallback, multi-model consensus assertions and video assertions. None publishes accuracy metrics.

### Cited Findings
- **antiwork/shortest**: MIT, 5,688 stars, TypeScript, last push 2026-08-06. The last release was v0.4.9 on 2025-04-01, and recent commits are chores (2025-06/08, 2026-05). It is a "natural language E2E testing framework" built on Playwright that runs on the Anthropic Claude API. ## Q5. Measuring check strength and verifier accuracy: mutation testing (Stryker, mutmut), property-based testing (fast-check, Hypothesis), eval harnesses (inspect_ai, promptfoo)

### Takeaway
StrykerJS is the best fit for seeding bugs into AI-written JS/TS web apps, because its default `command` test runner can run Contexer itself and use the exit code as the kill signal. The catch is that the command runner cannot do per-test coverage analysis, so every check runs for every mutant. mutmut covers Python backends but needs `fork`, which means WSL on Windows. LLMorpheus shows LLM-generated mutants that resemble real bugs, built on Stryker. inspect_ai (Python, MIT) is the natural harness for measuring catch rate and false-failure rate with logged, re-scorable runs. Hypothesis stateful testing can generate random UI action sequences checked against `no_errors`-style invariants.

### Cited Findings
- **stryker-mutator/stryker-js**: Apache-2.0, 3,206 stars, TypeScript, last push 2026-10-10 — [GitHub](https://github.com/stryker-mutator/stryker-js)
- The Stryker `command` test runner is the default: "runs a configurable bash/cmd command and bases the result on the exit code of that program" (`commandRunner: { command: 'npm test' }`). It "has no way of knowing more about your tests" and "just runs all tests for all mutants", so it gets no coverage analysis. `incremental: true` stores results in `reports/stryker-incremental.json`. `mutate` accepts globs and line ranges (`"src/app.js:1-11"`). Timeouts are `timeoutMS` (5000) and `timeoutFactor` (1.5). Runner plugins exist for Jasmine, Jest, Karma, Mocha, Tap, Vitest and Cucumber — [Stryker configuration docs](https://stryker-mutator.io/docs/stryker-js/configuration/)
- **boxed/mutmut**: BSD-3-Clause, 1,478 stars, Python, last push 2026-09-12, latest tag 3.8.0. It "Remembers work that has been done" and "Knows which tests to execute". It runs pytest. It "must be run on a system with `fork` support… on windows, you must run inside WSL". Code outside functions needs mutmut 2 — [GitHub](https://github.com/boxed/mutmut)
- **LLMorpheus** (Tip, Bell, Schäfer, arXiv 2404.09952, githubnext): an LLM proposes replacements at placeholder locations in JS/TS, and a modified StrykerJS applies and classifies them. On 13 subject applications it produced "mutants that resemble existing bugs" that standard Stryker mutators cannot. It needs an OpenAI-style API — [arXiv](https://arxiv.org/abs/2404.09952), [GitHub](https://github.com/githubnext/llmorpheus)
- **HypothesisWorks/hypothesis**: the GitHub API reports the license as NOASSERTION, 9,082 stars, Python, last push 2026-10-14 — [GitHub](https://github.com/HypothesisWorks/hypothesis)
- Hypothesis stateful testing uses a `RuleBasedStateMachine` with `@rule`, `@precondition`, `@invariant` (run after every step), bundles and `initialize`. Settings `max_examples` and `stateful_step_count` control run length. On failure it prints "a very short program that will demonstrate the problem", and it plugs into pytest through `TestCase` — [Hypothesis stateful docs](https://hypothesis.readthedocs.io/en/latest/stateful.html)
- **dubzzz/fast-check**: MIT, 5,201 stars, TypeScript, last push 2026-10-13. Model-based testing uses `fc.commands`, `modelRun`, `asyncModelRun` and `scheduledModelRun` ("to help detect race conditions"), with shrinking over the executed commands and replay through `{seed, path}` and `replayPath` — [GitHub](https://github.com/dubzzz/fast-check), [fast-check model-based testing](https://fast-check.dev/docs/advanced/model-based-testing/)
- **UKGovernmentBEIS/inspect_ai**: MIT, 3,003 stars, Python, last push 2026-10-14. A UK AI Security Institute framework that includes "model graded evaluations" and over 200 pre-built evals. Its scorers include `includes`, `match`, `pattern`, `exact`, `f1`, `model_graded_qa` and `model_graded_fact`, plus custom `Score` scorers. Metrics are `accuracy` and `stderr`. Logs can be re-scored with `inspect score` — [GitHub](https://github.com/UKGovernmentBEIS/inspect_ai), [Inspect scorers](https://inspect.aisi.org.uk/scorers.html)
- **promptfoo/promptfoo**: MIT, 25,996 stars, TypeScript, last push 2026-10-14 — [GitHub](https://github.com/promptfoo/promptfoo). OpenAI announced on 2026-03-09 that it is acquiring Promptfoo and folding it into its Frontier enterprise platform. Reports say the open-source project will continue, though one source says that is unclarified — [Security Boulevard](https://securityboulevard.com/2026/03/openai-acquires-security-startup-promptfoo-to-fortify-ai-agents), [Gigazine](https://gigazine.net/gsc_news/en/20260310-openai-to-acquire-promptfoo)
- Validity patterns from benchmarks:
  - SWE-Lancer runs "an automated check confirms each test passes on the fixed code and fails on the broken code" — [SWE-Lancer paper](https://arxiv.org/html/2502.12115)
  - "Are Autonomous Web Agents Good Testers?" mixes passing test cases with failing ones built from mutated apps, and reports correct-verdict rate and specificity — [arXiv 2504.01495](https://arxiv.org/abs/2504.01495)

### Inferences
- **Stryker: BUILD ON** for seeded-bug generation on JS/TS apps. Set `commandRunner.command` to a script that starts the app and runs Contexer's saved checks, exiting non-zero on any FAIL. Because every check runs for every mutant, restrict `mutate` to files touched by the goal (line ranges) and use `incremental`. Note that a mutant may break the build or app boot, which counts as a trivial kill. Report "killed by a behavioural check" separately from "killed by boot or compile failure".
- **mutmut: BORROW / limited.** Use it only for Python backends, and on Windows only under WSL. That matters here, because the team develops on Windows.
- **LLMorpheus: BORROW IDEAS.** LLM-written realistic bugs ("off-by-one in the cart total", "button wired to the wrong handler") make a better test of acceptance checks than arithmetic-operator swaps. Run each mutant through a SWE-Lancer-style validity filter: a reference oracle (hand-written Playwright test or human review) must confirm the mutant really breaks the goal. Otherwise equivalent mutants deflate the catch rate.
- **Metric definitions for Contexer's benchmark:** catch rate = share of valid seeded-bug variants where at least one check FAILs (sensitivity). False-failure rate = share of checks that FAIL on known-good builds, measured over repeated runs to separate flakiness from wrong checks (1 − specificity). Report both per verdict label (proven / LLM-judged / heuristic), since a judge that is wrong more often should be weighted down.
- **inspect_ai: BUILD ON** for the benchmark harness (Python, MIT, structured logs, re-scoring, `stderr`). **promptfoo: BORROW / optional**, best for prompt-regression tests of the goal-to-check compiler. It is Node, and its OpenAI ownership since March 2026 is a governance consideration.
- **Hypothesis: BORROW IDEAS / optional fuzz mode.** A `RuleBasedStateMachine` whose rules are Contexer steps on visible controls, with invariants such as `no_errors` and "no uncaught page errors", would find crashes that goal-derived checks miss, and Hypothesis shrinks a failure to a minimal sequence. **fast-check: AVOID** (Node). Its `scheduledModelRun` race-condition idea has no direct Playwright Python counterpart.

### Gaps
- I found no published study of mutation testing applied to browser-level end-to-end or acceptance suites for web apps, with measured mutation scores. All Stryker evidence concerns unit-test runners.
- Equivalent-mutant rates for LLM-generated mutants in front-end code were not found.
- Hypothesis's license field shows NOASSERTION in the GitHub API, and the actual license was not re-verified this session.

## Q6. Benchmarks that grade web apps end to end (SWE-bench Multimodal, SWE-Lancer, Web-Bench, FeatBench, WebGen-Bench, ArtifactsBench, FullStack-Bench, WebArena, plus 2026 additions): how do they grade?

### Takeaway
Grading falls into four kinds:
1. **Hidden unit or F2P/P2P tests:** SWE-bench Multimodal, FeatBench, and ByteDance's FullStack Bench.
2. **Hand-written Playwright end-to-end tests:** SWE-Lancer and Web-Bench.
3. **Agent-executed natural-language test cases:** WebGen-Bench, Vibe Code Bench and ViBench.
4. **MLLM-as-judge over rendered screenshots with per-task checklists:** ArtifactsBench.

WebArena moved from string and LLM matching toward deterministic state checks in WebArena Verified. The most important result for Contexer is that agent-evaluators disagree a lot. Vibe Code Bench reports 31.8–93.6% pairwise step-level agreement between evaluators.

### Cited Findings
- **SWE-bench Multimodal** (arXiv 2410.03859, 2024-10-04): 617 instances from 17 JavaScript libraries covering web UI, diagramming, data visualization, syntax highlighting and maps. Each instance has at least one image. SWE-agent resolved 12% at publication. A "Multimodal v2" entry dated 2026-09-01 says "The complete test split and evaluation tooling are open source" and that JS grading and "visual test-asset handling were made more robust" — [arXiv](https://arxiv.org/abs/2410.03859), [swebench.com/multimodal](https://www.swebench.com/multimodal.html). - **FullStack Bench** (ByteDance Seed, arXiv 2412.00535, v6 2025-05-12) covers 16 languages and domains such as data analysis, ML and math. It is graded by unit tests in the SandboxFusion sandbox and is not a browser end-to-end benchmark (bytedance/FullStackBench: Apache-2.0, 122 stars, last push 2025-05-07) — [arXiv](https://arxiv.org/abs/2412.00535), [GitHub](https://github.com/bytedance/FullStackBench)
- A different **FullStack-Bench** (FullStack-Agent paper, arXiv 2602.03798, 2026-02-03) "systematically tests the frontend, backend and database functionalities". FullStack-Dev reportedly beats the previous state of the art by 8.7% (frontend), 38.2% (backend) and 15.9% (database) on its test cases (mnluzimu/FullStack-Agent: 57 stars, no license) — [arXiv](https://arxiv.org/abs/2602.03798), [GitHub](https://github.com/mnluzimu/FullStack-Agent)
- **WebArena** (web-arena-x/webarena: Apache-2.0, 1,627 stars, last push 2025-11-26) has three evaluator families:
  - `StringEvaluator`: `exact_match`, `must_include`, and the LLM-based `fuzzy_match` and `ua_match`.
  - `URLEvaluator`.
  - `HTMLContentEvaluator` (`program_html`): checks required contents on the final page state through locators.
  - [evaluators.py](https://github.com/web-arena-x/webarena/blob/main/evaluation_harness/evaluators.py)
- **WebArena Verified** (NeurIPS 2025 workshop) re-audited the tasks and evaluators. It replaced fragile string checks with type-aware, normalizing comparators, checks backend state for tasks that change it, and adds 95% confidence intervals and failure-mode breakdowns. On the baseline agent it reduces false negatives by about 11%. Secondary sources say LLM-as-judge and substring checks were removed. Subset sizes conflict between sources (137 vs 258 tasks). ServiceNow/webarena-verified: Apache-2.0, 62 stars, last push 2026-03-08 — [NeurIPS listing](https://neurips.cc/virtual/2025/loc/san-diego/124576), [BenchLM](https://benchlm.ai/benchmarks/webarena-verified), [GitHub](https://github.com/ServiceNow/webarena-verified)
- **Vibe Code Bench** (Vals AI with MIT's Alex Gu, arXiv 2603.04601, v3 2026-05-13): 100 application specs (50 validation, 50 held-out test), with 964 browser workflows made up of 10,131 substeps. An "autonomous browser agent" evaluates them against the deployed apps. The best of 16 models scored 61.8% on the test split. Self-testing during generation predicts performance (Pearson r=0.72). Evaluator selection "materially affects outcomes", with 31.8–93.6% pairwise step-level agreement — [arXiv](https://arxiv.org/abs/2603.04601), [Vals blog](https://www.vals.ai/blogs/behind-the-scenes-of-vibe-code-bench)
- **ViBench** (CAIS 2026): tasks from production traces across 15 applications, covering both zero-to-one builds and feature extension. An "adaptive evaluator" uses REPL-based browser automation and reaches 99% step-level agreement with human experts across 1,082 test steps. Claude Opus 4.6 scored 46% Pass@1 and GPT-5.2 scored 42%. Only the abstract was available — [CAIS 2026 listing](https://caisconf.org/program/2026/papers/vibench-a-benchmark-on-vibe-coding/)
- **E2EDev** (ACL 2026, arXiv 2510.14509): fine-grained requirements, each with BDD (Gherkin) scenarios and Python step implementations, executed automatically with Behave. Built through human-in-the-loop multi-agent annotation. Code is at SCUNLP/E2EDev — [arXiv](https://arxiv.org/abs/2510.14509), [ACL Anthology](https://aclanthology.org/2026.acl-long.1618/)
- **ServiceNow/BrowserGym**: 1,401 stars, last push 2026-10-05. A Gym environment that unifies web-agent benchmarks — [GitHub](https://github.com/ServiceNow/BrowserGym)

### Inferences
- **Web-Bench: BUILD ON as a dataset** (Apache-2.0) for Contexer's seeded-bug benchmark. Its per-task Playwright specs are ready-made ground-truth oracles for validating seeded bugs, and its 20-step sequential projects mirror a coding agent extending an app.
- **WebGen-Bench: BORROW (dataset) for measuring the compiler.** Its 647 "operation + expected result" test cases are exactly the natural-language input Contexer compiles into checks. Measure whether compiled checks agree with its human-filtered expectations. Its missing license blocks redistribution.
- **SWE-Lancer: BORROW IDEAS.** Use its validity rule (the oracle passes on good code and fails on broken code) and its rationale that end-to-end checks are harder to game than unit tests. That supports Contexer's "proven = browser-executed" stance.
- **ArtifactsBench: BORROW IDEAS** for vision-judged checks: three-step temporal screenshots, per-task atomic checklists, and validating the judge against humans before using it at scale. It also shows that judge-model drift is real: the benchmark had to migrate off a deprecated Gemini preview judge.
- **WebArena Verified: BORROW IDEAS.** Contexer's comparators (equals, contains, matches, changed) should normalize by type, as WebArena Verified does. Report confidence intervals and failure-mode breakdowns in the benchmark.
- **Vibe Code Bench and ViBench** show that the choice of agent evaluator can move scores by large margins. This is the strongest outside evidence for Contexer's design: compile to deterministic checks where possible, label LLM-judged verdicts, and measure judge agreement on its own benchmark.
- **FullStack Bench (ByteDance): not relevant** (unit tests, not end-to-end). The mnluzimu FullStack-Bench is relevant for backend and database checks, but is unlicensed and lightly adopted.

### Gaps
- I did not read the details of SWE-bench Multimodal's test harness (F2P/P2P unit tests vs visual assets) or the 2026 v2 leaderboard. I believe grading is by repo tests as in SWE-bench, but this session did not confirm it.
- The size, judge model and grading of the mnluzimu FullStack-Bench were not in the abstract.
- I could not confirm whether Web-Bench ships reference solutions for each task, which matters for the "passes on good code" validity check.
- Vibe Code Bench's evaluator model and the cause of the 31.8–93.6% agreement spread were not available from the abstract.

## Q7. 2024–2026 research on self-healing locators, LLM-generated end-to-end tests, and LLM-as-judge for UIs

### Takeaway
The evidence base is thin and mostly preprints. LLM locator repair beats heuristics in small studies, and larger models do better. The one rigorous 2026 dataset, ReproBreak (449 reproducible Cypress and Playwright locator breaks), has no repair results yet. A March 2026 preprint argues for deterministic accessibility-tree re-extraction at zero LLM cost. LLM web agents acting as testers reach only about 60% correct verdicts, with high specificity. LLM and MLLM judges show a "significant gap" from human experts on web-dev quality (WebDevJudge, ICLR 2026), yet checklist-guided screenshot judging tracks human rankings well (ArtifactsBench). Contexer's labelling of judged verdicts is well supported.

### Cited Findings
- **ReproBreak** (de Moura, Adamietz, Mehboob, Noller, arXiv 2605.12158, v2 2026-08-31): mined 359 open-source repos for locator changes, reproduced the top 4 projects, and found 449 locator breaks (structural changes that break a locator while the functionality still works). It includes automated reproduction scripts and targets Cypress and Playwright. No repair results are reported — [arXiv](https://arxiv.org/abs/2605.12158), [dataset](https://github.com/rub-sq/ReproBreak)
- A secondary summary of the ReproBreak paper cites earlier work finding that "up to 75% of test files in Selenium-based setups require locator updates within nine commits" — [Emergent Mind summary](https://www.emergentmind.com/papers/2605.12158)
- **Zero-cost self-healing** (Joseph, arXiv 2603.20358, 2026-03-20): uses accessibility-tree extraction with a ten-tier locator priority (get_by_role, then data-testid, ARIA labels, CSS class fragments, visible text and so on) and re-extracts only broken selectors. It reports 31/31 passes on automationexercise.com across three device profiles, with re-discovery in under one second. This is a single-author preprint on one demo site — [arXiv](https://arxiv.org/abs/2603.20358)
- A systematic review of AI testing tools (arXiv 2409.00411) found that 32 tools (57% of those reviewed) offer AI-powered self-healing of UI test code — [arXiv PDF](https://arxiv.org/pdf/2409.00411)
- Helsinki master's thesis (Robot Framework): GPT-4 Turbo and Mistral Large repaired 87.5% of broken locators, while Mistral 7B repaired none — [Helda thesis PDF](https://helda.helsinki.fi/server/api/core/bitstreams/631b961a-8642-42ed-9826-3e196eac9cf7/content)
- Unverified secondary claim: an Analytics Insight article reports that an LLM healer recovered 55–68% of broken locators on Supabase Studio and Grafana, against 20–34% for text similarity and 23% for Healenium. The primary study was not found — [Analytics Insight](https://www.analyticsinsight.net/artificial-intelligence/suneet-malhotra-why-self-healing-test-systems-still-need-human-judgment)
- Practitioner guardrails:
  - PayPay: ask the LLM for a locator only when it is highly confident, using a JSON schema with a confidence threshold — [PayPay engineering blog](https://blog.paypay.ne.jp/en/ai-driven-self-healing-for-automation-testing-at-paypay/)
  - Ministry of Testing: a deterministic primary path, an AI fallback, and a validation layer before the test continues — [Ministry of Testing](https://www.ministryoftesting.com/insights/when-ai-maintains-your-tests-designing-safe-self-healing-automation)
- **"Are Autonomous Web Agents Good Testers?"** (Chevrot et al., arXiv 2504.01495, ISSTA 2025): three offline web apps and 113 manual test cases, some passing and some failing (mutated). Two agents, SeeAct-ATA and PinATA. PinATA reaches "around 60% of correct verdict" and "up to a promising 94% specificity", with persistent limitations in handling assertions and errors — [arXiv](https://arxiv.org/abs/2504.01495), [ISSTA 2025](https://conf.researchr.org/details/issta-2025/issta-2025-papers/10/Are-Autonomous-Web-Agents-good-testers-)
- **AutoE2E** (UBC, ICSE 2025, arXiv 2408.01894): infers features and generates feature-driven end-to-end tests, reporting 79% average feature coverage on E2EBench (8 apps), 558% over the best baseline. VISCA (arXiv 2506.04161) follows up on it — [arXiv](https://arxiv.org/abs/2408.01894), [ICSE 2025](https://conf.researchr.org/details/icse-2025/icse-2025-research-track/61/Feature-Driven-End-To-End-Test-Generation)
- LLM web-form test generation (ASE 2025 journal-first, arXiv 2405.09965): 11 LLMs on 146 forms from 30 Java web apps. GPT-4, GLM-4 and Baichuan2 were best, and the others had successful-submission rates 9.10%–74.15% lower — [ASE 2025](https://conf.researchr.org/details/ase-2025/ase-2025-journal-first-track/36/Large-Language-Models-for-Automated-Web-Form-Test-Generation-An-Empirical-Study)
- Page-object generation with GPT-4o and DeepSeek Coder (arXiv 2602.19294) reached 32.6–54.0% accuracy, with element recognition above 70% in most cases — [arXiv PDF](https://arxiv.org/pdf/2602.19294)
- **WebDevJudge** (Li et al., Tencent AI Lab and others, arXiv 2510.18560, ICLR 2026 oral) studies judges in both static-observation and interactive settings. It found "a significant gap" between LLM, MLLM and agentic judges and human experts, citing failure to recognize functionally equivalent implementations, failure to verify feasibility, and bias. Code is at lcy2723/WebDevJudge — [arXiv](https://arxiv.org/abs/2510.18560v1), [ICLR 2026](https://iclr.cc/virtual/2026/oral/10010880)
- ArtifactsBench reports over 90% pairwise judge agreement with human experts and 94.4% ranking consistency with WebDev Arena, using checklist-guided MLLM judging of temporal screenshots — [arXiv](https://arxiv.org/abs/2507.04952)
- Vibe Code Bench reports 31.8–93.6% pairwise step-level agreement between evaluators — [arXiv](https://arxiv.org/abs/2603.04601). ViBench reports 99% step-level agreement for its adaptive REPL evaluator (abstract only) — [CAIS 2026](https://caisconf.org/program/2026/papers/vibench-a-benchmark-on-vibe-coding/)

### Inferences
- **Self-healing locators:** the research supports a deterministic-first cascade (Browser Use style, or the ten-tier accessibility-tree hierarchy) followed by a confidence-gated LLM fallback over an ARIA snapshot. Every healed locator should be validated against the stored fingerprint before the original expectation runs. **ReproBreak: BUILD ON as an evaluation dataset** for Contexer's re-location feature, measuring correct re-location and wrong-element rates on 449 real breaks. Its license should be checked first.
- **Agent-as-tester accuracy** (about 60% correct verdicts, 94% specificity) means free-form LLM agents rarely raise false alarms but often miss bugs or fail to execute steps. Contexer's compile-to-checks design pushes the verdict into deterministic Playwright assertions, which should raise sensitivity. The seeded-bug benchmark should report sensitivity and specificity in the same way so results are comparable.
- **LLM-as-judge for UIs:** judging works when it is checklist-constrained and grounded in screenshots (ArtifactsBench), and is unreliable for open-ended quality judgments (WebDevJudge). For vision-judged checks, Contexer should compile each visual expectation into atomic checklist items, judge them over before, after and final screenshots, and label them LLM-judged. Consensus or fail-on-disagreement (Bug0 pattern) can reduce the false-pass risk.

### Gaps
- I found no peer-reviewed head-to-head comparison of LLM, heuristic and Healenium locator repair on Playwright suites. The 55–68% figure is from an unverified secondary article.
- No study measures the "check weakening" risk, meaning healers that pass by retargeting to the wrong element or relaxing assertions. This is a gap Contexer could fill with ReproBreak plus seeded bugs.
- No research found evaluates LLM-generated acceptance checks (as opposed to test scripts) for catch rate against seeded bugs in AI-written apps.
